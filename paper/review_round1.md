## 1. 总评（Summary）

本文提出"谱即序列"框架：将光谱按物理波长离散为 token 序列，经零初始化交叉注意力注入冻结 CLIP ViT，在每类 5 个标注像素下于 Pavia U / Indian Pines 达到 50.8%/50.1% mIoU；并以 tokenize 消融、内核对照与 2×2 因子实验论证"波长对齐 × 序列内核"的跨传感器迁移机理；提出 TSC 转导正则缓解 5-shot base-novel 坍缩；同时给出分层评测协议与 50/50 held-out 上界。论文最突出的品质是诚实性：约 20 处关键数字经与结果 JSON 二次核对全部吻合（仅 2 处弱来源），负面结果（跨场景零样本失败、MLP 域内更优、TSC β 非单调）均入正文并参与论证。但按 CCF-A 标准衡量，证据强度存在系统性短板：全部结论建立在单种子之上；核心机理比值定义在近零分母（7.57% mRecall）上且 2×2 因子矩阵缺一格；主表没有任何同协议外部方法对比，甚至缺少光谱 kNN 这类 trivial 下界；转导成分（类均衡推理）的施加范围在表格间口径不一致，且材料中存在两个差异显著的 Pavia RGB 基线（3.4% 与 5.5%）而论文只报告了更低者且未作解释——这直接威胁"15×"这一头条数字的可信度。TSC 的两个成分未消融，贡献 3 的归因链条断裂。写作整体清晰，但"开放词汇"主张在标题与摘要层面未限定于同场景设定。

## 2. 总体推荐

**Weak Reject（按 CCF-A 现行标准）。**

理由：问题设定真实、协议自省与诚实性达到罕见水准、数字与工件一一对应，这些是超出平均投稿的优点；但（i）单种子 + 近零分母比值上的机理结论、（ii）零外部基线对比、（iii）转导成分披露口径问题、（iv）TSC 无成分归因，四项中任何一项单独都足以让 CVPR/ICCV 审稿人给出 borderline 以下评分。若 P0 清单（§7）全部落实，本稿有条件进入 Borderline+/Weak Accept 讨论；对 TGRS/ISPRS JPRS，现稿相当于 major revision。

## 3. 优点

1. **数字可核验性极佳**：抽查 20 项论文数字与结果 JSON，18 项精确吻合、2 项弱来源但已在自检清单声明；"结果文件名编码全部变量、必须披露评测/训练像素相交、零样本基线同推理预算"三条协议红线是真实踩坑后的制度化，值得作为基准论文的贡献保留。
2. **负面结果的处理是同类工作中的模范**：MLP 域内更优（54.2% > 50.8%）没有回避，而是转化为"域内精度与迁移能力解耦"的条件化结论，正面回应了 [Tan et al., 2024] 的内核无用论；跨场景零样本失败（含全监督冻结 0.18%）被用作"源场景过拟合"的解释证据而非隐藏项。
3. **2×2 因子化消融的设计意识正确**：把 tokenize 与内核拆为两个因子、以 bandeq9（同 token 数、无对齐）隔离物理对齐变量，这是对"整体消融无法归因"这一常见审稿意见的预先防御；bandindex×mlp 缺格如实标注"未测"。
4. **base-novel 坍缩的刻画干净且有增量**："novel mIoU 精确为 0.0、早停无效、三种常规手段此消彼长"是一个清晰的现象学贡献，TSC 用光谱流形结构（而非 RGB 空间平滑）做转导正则的切入点有 HSI 特异性。
5. **训练/推理成本披露完整**（7.46M 参数、26 秒、2.7GB、单卡），"单卡极少标签"的定位诚实且与数字自洽。

## 4. 主要问题（Major Issues）

### M1 转导成分披露口径不一致；Pavia RGB 基线存在两个版本，"15×"头条数字的对照物未澄清

- **问题**：§3.3 与 §4.2 声称类均衡推理"对本文方法与全部基线（含 RGB 直用 CLIP）一致施加并披露"，但表 2（Tier 1 主表）没有任何一行标注是否施加均衡推理。更严重的是，工件中存在两个 Pavia RGB 基线：`pilot_v1/rgb_baseline_paviau.json`（mIoU 3.38%/OA 9.28%，表 2 采用）与 `pilot_v2/rgb_baseline_paviau.json`（mIoU 5.50%/OA 13.37%，即表 6 RGB 行的同文件，该行明确标注"+均衡推理"）。IP 的两版基线数字完全相同（2.59%/8.73%/7.57%），说明管线未变——那么 Pavia 的 3.4%→5.5% 差异只能来自配置差异（最可能是均衡推理），而论文对 5.5% 这一数字只字未提。若主结果 50.8% 含均衡推理而基线用不含均衡的 3.4%，"约 15 倍"即为不公平对比（同预算对照应为 50.8/5.5≈9.2×）；若 50.8% 不含均衡推理，则 §3.3 的一揽子声明与表 2 矛盾。两种情况都必须澄清。
- **证据**：`results/pilot_v1/rgb_baseline_paviau.json` vs `results/pilot_v2/rgb_baseline_paviau.json`（后者含 base_novel 字段、`calibrate:false`，其 base/novel 值 7.17/3.41 与表 6 "RGB+均衡"行一致）；`results/pilot_v1/rgb_baseline_indianpines.json` 与 `results/pilot_v2/rgb_baseline_indianpines.json` 逐位相同。
- **修改指令**：(a) 表 2/3/4/6/7 每行增加"均衡推理：是/否"标注；(b) 报告注入式 5-shot 的含/不含均衡推理两个版本的主结果；(c) 在 §4.1 或 §4.2 明确解释两版 Pavia RGB 基线差异的根源（配置逐项列出），并说明全文统一采用哪一版、为什么；(d) 据此重算并修正摘要/引言/贡献 1 中的倍数声明。

### M2 全部机理结论建立在单种子之上；"超加性"在缺格、无方差的 2×2 上不构成统计结论

- **问题**：表 3（tokenize 排序）、表 4（内核对照）、表 5（2×2）、表 6（TSC β 非单调）均为 seed 0 单次运行。论文自己承认（§6.3）方差未量化，但仍以 1.75×/1.27×/1.21× 的两位精度陈述"超加性增益"，且 2×2 的 bandindex×mlp 格未测。mRecall 比的分母是 7.57% 的近零基线——本文 §5.4 自己论证过"基线近零时绝对数无判别力"，这一论证同样适用于比值本身：7.57% 分母上的比值方差极大，0.57×与 0.98× 的排序在任何种子扰动下都可能翻转。域内差距（50.8 vs 54.2，MLP 更优）也完全在 5-shot 单种子噪声范围内。
- **证据**：所有 innovation/*.json 的 tag 均为 seed0；docs/08 全部表格单列 seed0；§6.3 自认"主要结果为单种子"。
- **修改指令**：(a) 对表 3/4/5 的全部格子与表 6 的 TSC 三档做 ≥3 seeds，报告 mean±std，把不显著的排序差异（如 wl25 vs bandeq9）明确降级；(b) 补跑 bandindex×mlp 格子，补齐 2×2；(c) "超加性"表述改为"在观测种子下超过两因子单独增益之和（1.54×），待多种子确认"；(d) 若多种子后 MLP 与 Transformer 域内差异不显著，§5.2 的"序列内核是纯过拟合容量"表述需相应软化。

### M3 无任何同协议外部方法对比，且缺少 trivial 下界基线

- **问题**：主表（表 2）只有 RGB 直用 CLIP 与自家池化式适配器两个内部基线。SPECIAL（有官方代码）、HSI-Adapter、SegEarth-OV 全部被 §4.3 的红线排除在表外"仅作上下文"，监督 HSI 模型只作口头参照。审稿人无法判断 50.8% 在该协议下是高是低。更基本的是：5-shot 设定下存在一个显而易见、零训练的 trivial 基线——45 个标注像素的光谱 1-NN / 余弦相似度分类器（在 unit-RMS 谱形上）——它既不需要 CLIP 也不需要训练，是"谱结构携带判别信息"这一核心主张的自然检验，论文没有比。若光谱 kNN 已能到 30-40%，则 7.46M 参数叙事的说服力被削；若它很低，则是支撑本文的免费证据。无论结果如何都必须报告。
- **证据**：BENCHMARK.md 基线清单仅 4 项且第 4 项为"引用数字不混表"；`results/` 中无任何 SPECIAL/kNN 运行记录；docs/05 §3 自认 CCF-A 需要"与 SegEarth-OV/HSI-Adapter 的完整对比"。
- **修改指令**：(a) 在 unit-RMS 谱形上跑每类 5 像素的 1-NN（余弦/欧氏）基线，入表 2；(b) 至少将 SPECIAL 按本文协议复现一版（输入端插值 RGB + CLIP，训练/评测预算对齐），入表 2 或单独小表；(c) 将监督 HSI 专用模型（如 SpectralFormer 同预算微调）作为上界行加入表 8；(d) 若确无法复现竞品，需在正文给出量化的不可比性论证而非仅协议声明。

### M4 方法描述不足以复现；工件元数据与论文 token 数矛盾

- **问题**：§3 未给出：优化器与学习率、训练 epoch 数（§3.2 提到 5 epochs 但未作为默认超参声明）、batch/crop 采样方式（45 个像素如何产生 32×32 crop、是否增强）、文本 prompt 模板、7.46M 的参数分解（编码器/注入层/QKV 投影各多少）、注入注意力的 head 数与序列长度细节、45/80 个训练像素的采样种子与空间分布。可训练参数量与训练时长只存在于 docs/05，v2 结果 JSON 中无 `trainable_params_M` 字段（v1 JSON 有 0.3348M）。表 3 宣称 token 数为 5/9/17/9/16，但全部 tokenize 变体 JSON 的 `bins` 字段均为 9——工件无法核验 token 数，也无法排除元数据记录错误。无代码发布声明。
- **证据**：`innovation/train_metrics_*_wl100/wl25/bandeq9/bandindex_*.json` 的 `bins:9`；`innovation/*.json` 无 params/train_time 字段；§3 全节无优化细节。
- **修改指令**：(a) 增补实现细节附录（或扩充 §3）：全部超参表 + 参数分解表 + 训练像素选择协议 + prompt 模板；(b) 修正结果 JSON 的 tokenize 元数据或注明 bins 字段为陈旧默认值；(c) 投稿附代码链接（CVPR 复现检查表必填）。

### M5 TSC 两成分未消融，贡献 3 的归因链条断裂；"首次刻画坍缩"忽视广义零样本学习文献

- **问题**：贡献 3 的核心是 TSC，但其邻域一致性项与边际均衡项从未单独施加（§6.2 自认"框架层面的假说"）。存在一个具体的竞争性假说未被排除：novel 存活可能完全由边际均衡驱动、与光谱 kNN 图无关——若如此，"利用 HSI 谱流形结构"的核心卖点（摘要、§3.3、§6.2 反复强调）失去支撑，且该消融在 n_trans=120 的规模下计算成本几乎为零，不做无法辩解。此外，"首次刻画极 few-shot 下的 base-novel 坍缩"过强：广义零样本学习（GZSL）对 seen-class 偏置与校准（如 calibrated stacking）有长期系统研究，few-shot 适配摧毁零样本先验也是 CLIP 适配文献的已知现象；本文的增量在于"光谱流形上的转导正则"而非"刻画坍缩"本身。相关工作只引了 ZS3Net，未覆盖 GZSL 校准一线。
- **证据**：§6.2"两个成分尚未单独消融……目前无法判定"；§1 贡献 3"首次刻画"；§2.4 无 GZSL 引用。
- **修改指令**：(a) 立即补三组消融：仅 L_cons / 仅 L_marg / 无 kNN 图（随机配对），将结果写入表 6 并按结果重写 §6.2——若 TSC 退化为边际均衡，须把摘要与贡献 3 中"谱流形"表述删除；(b) §2.4 增补 GZSL seen-bias/校准文献，贡献 3 的"首次"限定为"首次在开放词汇 HSI 分割设定下"。

### M6 模型选择协议未披露；空间自相关对 Tier-1 与 held-out 上界的支撑未讨论

- **问题**：论文未说明任何超参（epoch、lr、β、λ、注入层位 3/6/9、50nm bin）是在哪个数据集合上选择的。若在评测集上选择（5-shot 下极易发生），Tier-1 存在选择泄漏；这比"评测含 45 个训练像素"（已披露）严重得多。其次，全部评测为逐像素口径：45 个训练像素的空间近邻（同材质相邻像素光谱近乎复制）大量存在于评测集，5-shot 的 50.8% 部分由空间-光谱自相关支撑；50/50 held-out 上界为随机像素对半分，99.93% 的数字在空间分块划分下会显著下降。这两点用于"上界标定/架构对比"时相对结论（65 vs 99.9）仍成立，但绝对数字的解读必须加限定。
- **证据**：§4.2/§4.3 无模型选择条款；BENCHMARK.md 同；表 8 的 split 为 seed 123 随机对半，无空间约束。
- **修改指令**：(a) 在 §4 增补"模型选择"条款：声明所有超参的选择依据（固定预算、独立验证像素或文献默认），如曾在评测集上试错选择则必须如实披露并改为验证集选择；(b) 增加一个空间分块（如按 20×20 block）的 held-out 变体，验证上界结论的稳健性，或在 §4.3/§6.3 明确写出空间自相关限定。

### M7 "开放词汇"主张在标题/摘要/结论层面未限定于同场景；协议承诺的预算点缺测

- **问题**：标题为"开放词汇高光谱分割"，摘要先陈述 50.8%/50.1% 再谈开放词汇，仅以"跨场景零样本迁移仍不成立"一句带过——但 §5.4 的结论是本方法的开放词汇能力仅在"同场景 base-novel"（Tier 2）上成立，跨场景与跨传感器全部失败。按现稿表述，扫读者会得出比实际强得多的印象。这是主张-证据对齐问题，不是数据造假问题，但顶会审稿人对标题级 overclaim 零容忍。另外 §4.2 协议承诺 Tier 1 覆盖 k∈{5,15,50}，而本文方法（注入式）的 Tier 1 证据只有 k=5；50-shot 只存在于 base-novel 配置，封闭集 15/50-shot 曲线对 v2 完全缺失（§6.3 表述"标注预算只有 5 与 50 两个点"与实际不符——v2 的 50 点并非 Tier 1 口径）。
- **证据**：标题；摘要第 4-6 句；`results/pilot_v2/` 与 `innovation/` 中无 v2 封闭集 s15/s50 文件；docs/05 §3 自认"论文定位应为标签效率前沿分析而非 5-shot 开放词汇 SOTA"。
- **修改指令**：(a) 标题加入限定（如 "Label-Efficient Open-Vocabulary ... within-Scene"）或摘要首段即明确"开放词汇主张限于同场景 base-novel，跨场景零样本不成立（如实报告）"并前置；(b) 结论第一句同改；(c) 补 v2 注入式在 k∈{15,50} 的 Tier 1 封闭集结果（成本极低：26 秒/次），或将 §4.2 的 k 集合改为实际交付的 {5}。

6. **"该归一化本身是协议贡献"（§5.2）措辞过强**：相对自身基线的比值在近零基线下使用是评测惯例，建议降为"协议规范"。
